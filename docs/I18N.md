# Internationalization — OpenStrata

OpenStrata ships its own locale catalog at `src/lib/i18n.ts`. It does not
depend on the Give A Bit master translation repository.

## Supported locales

`en` (default), `fr`, `es`, `zh`, `hi`, `fil`, `pl`, `uk`, `sw`.

## How it works

- `src/lib/i18n.ts` defines the `Translation` type, the English catalog
  (single source of truth), and per-locale override objects.
- Non-English locales override English keys; any key without an override
  falls back to English automatically.
- `$copy` is a derived store; `$copy.key` in templates re-renders on locale
  change. `locale.set(code)` persists the choice to `localStorage`
  (`openstrata-locale`).
- Locale-aware formatters: `formatNumber`, `formatCurrency` (CAD),
  `formatDate` — use per-locale `Intl` regions (en-CA, fr-CA, es-419, …).

## Rules

1. **Interface copy lives in the catalog.** No hard-coded English in route
   templates — `npm run audit:i18n` warns on hard-coded text nodes,
   placeholders, and meta content.
2. **Domain records stay canonical English** until reviewed translations
   exist: statutory content in `src/lib/compliance.ts`, `strata-tool.ts`,
   `marketing.ts`, `data.ts`, and page-level data arrays is intentionally
   not machine-translated.
3. **Legal/statutory translations require professional review** before being
   marked reviewed or published.
4. Add a key to the `Translation` type + English catalog first, then add
   overrides per locale. Run `npm run audit:i18n` before pushing.

## Audit

`npm run audit:i18n` checks that every `$copy` usage resolves to a catalog
key (error-level) and scans routes for hard-coded interface copy
(warn-level). The audit must pass before release.
