## Recent milestone — migration `0009` failed its first real run, and the runner is why (backend, `d220d6f`)

- **The previous session's handoff was wrong about the most important thing.** It claimed migration `0009` had "never been executed anywhere". It had been executed: CI's `Phase 3 backend — Postgres e2e smoke` job ran it on that push and it **failed** — `FAILED 0009_audit_log_and_sessions.sql`, `syntax error at or near "RAISE"` (`42601`, `plpgsql_yyerror`, character 2577). So the push left `main` red, the smoke suite never ran, and the sessions/audit tables existed nowhere. "Never executed" and "executed and rejected" are different failures with different fixes.
- **The bug was in `scripts/migrate.mjs`, not in the migration.** The runner strips standalone `BEGIN`/`COMMIT` lines so that a migration's DDL and its version row commit in one transaction. It did that with a line filter, and a plpgsql body is written as `BEGIN … END;` inside `$$ … $$` — so the `BEGIN` opening the append-only trigger function was deleted and its `RAISE EXCEPTION` was left with no block to belong to. `0009` is the first migration carrying a function body, so the flaw had been latent since `0008`.
- **The stripper now reads SQL quoting instead of lines.** `stripTransactionWrappers` carries quoting state across lines — line comments, nestable block comments, single-quoted strings, double-quoted identifiers, and dollar-quoted bodies including the tagged `$body$` form — and removes only a wrapper that begins in plain SQL context. `scanLineState` is exported next to it. Four tests in `backend/tests/migrate.test.ts` cover the plpgsql case, quoted `COMMIT` in strings/identifiers/tagged bodies/comments, and an invariant over the shipped migrations: every quoted segment must survive the stripper byte-identical.
- **Migration `0009` has now been executed for real.** PostgreSQL **17.11** with **pgvector 0.8.7** — the CI image's major version — was installed locally, a fresh cluster took `npm run migrate` through `0001..0009`, the re-run reported `no pending migrations`, and `npm run migrate:check` came back clean. ## Prior milestone — sessions a council can end, and a record of who did what (backend, `8d5c6b4`, `8bdf968`)

- **A token can be revoked now.** Every token carries a `sid` naming a row in `auth_session` (migration `0009`) that every request resolves: it must exist, be unrevoked and unexpired, belong to the claimed user and council, and still carry the token's role. `POST /auth/logout` ends a session immediately instead of at token expiry, a role change ends it, and a refresh token presented twice ends it as a stolen copy. Access tokens are short-lived (`AUTH_TOKEN_TTL`, default **1h**, was 12h) and renewed with a refresh token issued once, stored only as a SHA-256 hash, and rotated on every use (`AUTH_REFRESH_TTL_DAYS`, default 30). New: `GET /auth/sessions` (own sessions, current one marked) and `DELETE /auth/sessions` (sign out everywhere else).
- **Privileged actions leave a row now.** Twenty routes were role-gated — ledger posts, billing runs, bylaw fines, unit and member deletion, user management — and none recorded the actor. `audit_event` (migration `0009`) holds actor, role, action, outcome, target, status, IP and user agent, written by one `onResponse` hook over one pure policy (`src/audit/policy.ts`). The default is to record, so a new endpoint is audited unless explicitly exempted; refusals are rows too; request bodies are never copied in; unattributable traffic is not recorded at all except the two rate-limited auth events. `GET /api/v1/audit/events` (admin) reads it back, tenant-scoped and cursor-paged.
- **`PATCH /api/v1/auth/users/:id`** adds the admin role change — the demotion path that makes revocation matter — refusing a self-change (`409`) and leaving the council with no admin (`409`), and revoking the target's sessions on the change.
- **The site's sign-out is real sign-out** (`8bdf968`): `signOut()` ended nothing on the backend before, so a cleared token stayed valid for its whole lifetime.

- **`/accounting` is now fully in the catalog; five routes still are not.** The six dashboard routes listed under the i18n milestone render English in every locale except `/accounting`, which shipped its copy in `0.3.40` — `/units`, `/pay`, `/tax`, `/calendar` and `/meetings` remain, and the audit names each string on every run.
- **The demo `money()` helper is not locale-aware.** A French page still shows `$904.58` rather than `904,58 $`; `formatCurrency` in `src/lib/i18n.ts` does it properly and is used where formatting matters. Localizing money and dates across the demo statements is item 47 on the improvements list.
- **Migration execution now repeats on every push, on this machine.** `npm run db:check` applies the whole set from zero and as an upgrade and runs the suite against the result in ~3s, and `.githooks/pre-push` runs it — installed in this clone (`core.hooksPath=.githooks`), so another clone or machine needs `npm run hooks:install` once. CI's `backend-e2e` job runs the same gate on a fresh `pgvector/pgvector:pg17` container (it replaces the separate `npm run migrate` and `-- e2e-smoke` steps), so CI and the hook agree on what "applies" means. What is still not covered: the harness is Homebrew-shaped — `OPENSTRATA_PG_BIN` or a `DATABASE_URL` pointing at `docker compose`'s `db` service are the non-macOS paths.
- The audit row for a bylaw fine carries the amount and the council-minutes reference, but **not the unit** — the complaint is an opaque JSON string the policy deliberately does not parse. Traceability for a fine runs through the minutes, not the lot.
- The site consumes `POST /auth/logout` but **not refresh tokens**: an access token simply expires after an hour and the next call 401s into a signed-out state. That is a UX decision left open, not a broken path.
- There is no UI for the audit trail or the sessions list. Both are API-only, and an admin reads them with `curl` today.
- `backend/package.json` is now `0.3.28`: the version was bumped with the migration-runner fix (`d220d6f`) rather than leaving a third release on the stale `0.3.27`. The site version stays on its own track at `0.3.37`.
- `npm run check:security` is green and runs in CI, and its blind spot is named where it lives: a real key written as a friendly slug with no danger word (`internal-db-passphrase-2026`) is classified as a fixture. It is counted on every run (`21 in 18 files` today), so a jump is visible rather than silent.
